# REDLINE — คู่มือภาษาไทย

**REDLINE** คือหน้าปัดดิจิทัลสไตล์รถแข่งสำหรับบอร์ด **CYD (ESP32-2432S028R)** จอ 2.8" 320×240 ทัชสกรีน
แสดงรอบเครื่อง ความเร็ว เกียร์ อุณหภูมิ และแรงดันไฟ
มีตัวจำลองในตัว, เปลี่ยนธีมได้ 3 แบบ, และรับค่าจริงได้ 4 ทาง (OBD-II บลูทูธ, Serial, เซ็นเซอร์ต่อตรง, โค้ดของคุณเอง)

## 1. แฟลชลงบอร์ด

```bash
ls /dev/cu.*                     # หาพอร์ต (เลขเปลี่ยนทุกครั้งที่เสียบคนละช่อง)
~/.platformio/penv/bin/pio run -e esp32dev -t upload --upload-port /dev/cu.usbserial-XXXX
~/.platformio/penv/bin/pio device monitor     # ดู log ที่ 115200
```

| env | ใช้เมื่อ |
|---|---|
| `esp32dev` | จอที่ต้อง invert สี (บอร์ดตัวแรก) |
| `cyd-noinvert` | จอสีปกติ — ถ้าแฟลชแล้วสีกลับ (พื้นดำกลายเป็นขาว) ให้ใช้ตัวนี้ |

## 2. การใช้งานบนจอ

| ทำอะไร | ผล |
|---|---|
| แตะปุ่ม **⚙ SETUP** (มุมขวาล่าง) หรือแตะแถบสถานะด้านบน | เปิดหน้าตั้งค่า |
| กดค้างบริเวณหน้าปัดหลัก (โหมด SIM TOUCH) | เป็นคันเร่ง — ยิ่งกดไปทางขวายิ่งเร่งแรง ปล่อยนิ้ว = ถอนคันเร่ง |
| กดค้าง ~1 วินาทีที่หน้าปัดหลัก (โหมดอื่น) | รีเซ็ต PEAK RPM |

### หน้าเปิดเครื่อง (splash)
ตอนเปิดเครื่องจะขึ้นโลโก้ REDLINE บนธีมที่เลือกไว้ แถบรอบเล็กๆ วิ่งเต็มเป็นตัวบอกความคืบหน้า มีเครดิต *crafted by birdlab.th*
แสดงประมาณ 1.8 วินาที แตะข้ามได้หลังผ่านไป 1 วินาที
เครดิตนี้เป็น **Required Notice** ของสัญญาอนุญาต (ดู [NOTICE](NOTICE)) จึงปิดไม่ได้
ถ้าเอา splash ออกหรือแก้โลโก้ แถบสถานะจะขึ้น `UNOFFICIAL` แทนชื่อ REDLINE

### หน้าตั้งค่า (บันทึกลงหน่วยความจำ ปิดเปิดใหม่ยังอยู่)
- **THEME** — แตะรูปตัวอย่างเพื่อเปลี่ยนธีม เปลี่ยนทันทีทั้งพื้นหลัง บาร์รอบ ตัวอักษร
- **DATA SOURCE** — เลือกแหล่งข้อมูล (ดูหัวข้อ 3)
- **SHIFT LIGHT RPM** — รอบที่ไฟเตือนเปลี่ยนเกียร์ ปรับทีละ 250
- **BRIGHTNESS** — ซ่อนไว้ เพราะไฟหลังจอ CYD ดับทันทีเมื่อหรี่ด้วย PWM จึงเปิดเต็มตลอด ถ้าบอร์ดที่ใช้หรี่ได้ ตั้ง `BACKLIGHT_DIMMING 1` ใน `config.h` จะได้ปุ่มปรับ 20–100% กลับมา
- **BEEP ON/OFF** — เสียงเตือน, **RESET PEAK**, **DONE** กลับหน้าเกจ

### ความหมายของสีและสัญญาณ
- **จุดสีบนแถบสถานะ**: เขียว = รับค่าจริงอยู่ · สีธีม = โหมดจำลอง · เหลืองกระพริบ = กำลังเชื่อมต่อ · แดง = ผิดพลาด
- **ข้อความมุมขวาบน**: เวลาที่ใช้งาน หรือสถานะ เช่น `BT PAIRING`, `ELM INIT`, `ECU SEARCH`, `NO ADAPTER`, `NO ECU`, `WAIT DATA`, `NO INPUT`
- **รอบถึง SHIFT RPM**: บาร์กระพริบแดง ตัวเลขรอบเป็นสีแดง ไฟ LED บนบอร์ดกระพริบแดง + เสียงบี๊บ
- **ค่าเกินเกณฑ์**: สีเหลือง = เตือน, แดงกระพริบ = อันตราย, LED กระพริบสีส้ม + บี๊บ 1 ครั้ง
- **น้ำหล่อเย็นยังเย็น** (< 60 °C): ตัวเลขเป็นสีฟ้า
- **ค่าไม่อัปเดตเกิน 2.5 วินาที**: แสดง `--` (จอจะไม่ค้างค่าเก่าหลอกตา)

## 3. แต่ละโหมดทำงานยังไง

![REDLINE รับข้อมูลจากที่ไหนบ้าง](docs/wiring/system-overview.svg)

ทุกโหมดส่งค่าเข้า "bus" กลางตัวเดียวกัน (`src/data/gauge_bus`) — หน้าจอ, การเตือน, peak, การประมาณเกียร์
ทำงานเหมือนกันหมดไม่ว่าค่ามาจากไหน โหมดต่างๆ รันใน task แยกบน core 0 ส่วนจอรันบน core 1
จึงไม่มีโหมดไหนทำให้จอกระตุก (แม้ตอนบลูทูธกำลังค้นหาอุปกรณ์)

### SIM (SIM AUTO) — จำลองการขับอัตโนมัติ
จำลองฟิสิกส์รถจริง: กราฟแรงบิดเครื่อง, เกียร์ 6 สปีดเปลี่ยนเอง, คิกดาวน์, คลัตช์ออกตัว, แรงต้านลม, เบรก,
ความร้อนน้ำ/ไอดี, ไฟชาร์จ ตอนเริ่มมีสตาร์ทเครื่อง (ไฟตกเหลือ ~10.6 V แล้วรอบกระชาก)
วนสคริปต์: เดินเบา → ขับในเมือง → กดสุดผ่านไฟเปลี่ยนเกียร์ → เบรก → ทางด่วน
**ใช้ทำอะไร**: โชว์/ทดสอบจอ ไม่ต้องต่ออะไรเลย

### TOUCH (SIM TOUCH) — จำลองโดยใช้นิ้วเป็นคันเร่ง
รถจำลองตัวเดียวกัน แต่คุณเป็นคนเหยียบ: กดค้างที่หน้าปัด = เร่ง (ขวาสุด = เต็มคันเร่ง) ปล่อย = ชะลอ
**ใช้ทำอะไร**: เล่นดูไฟเปลี่ยนเกียร์ / ทดสอบค่า SHIFT RPM ที่ตั้งไว้

### SERIAL — รับค่าผ่านสาย USB
ส่งข้อความทีละบรรทัดเข้า USB (115200) จากคอมพิวเตอร์ / Raspberry Pi / ไมโครคอนโทรลเลอร์ตัวอื่น:
```
rpm=3200 spd=86 clt=87 volt=13.9 iat=42 gear=3
{"rpm":3200,"speed":86,"coolant":87,"voltage":13.9}
```
ส่งค่าไหนก็ได้ ไม่ต้องครบ ชื่อที่รองรับ: `rpm` · `spd/speed/kmh` · `clt/coolant/ect` · `v/volt/voltage/batt` · `iat/intake` · `gear` · `tps/throttle`
ทดสอบจาก Mac: `~/.platformio/penv/bin/python tools/serial_feed.py /dev/cu.usbserial-XXXX`
**ต่อจาก Arduino / บอร์ดอื่น**: ต่อ TX ของบอร์ดนั้น → **GPIO 27** ของ CYD (ช่อง CN1) + GND (ช่องรับอย่างเดียว ไม่แย่ง USB)
มีตัวอย่าง sketch พร้อมวิธีต่อสายใน **[examples/](examples/README.md)**: `SerialSenderDemo` (ค่าทดสอบ) และ `SerialSenderSensors` (รอบ, ความเร็ว, แบต, อุณหภูมิ)
บอร์ด 5V (Uno/Nano) ต้องใส่ตัวต้านทานแบ่งแรงดัน 1k/2k ที่ขา TX

![ต่อ Arduino Uno / Nano เข้า CYD](docs/wiring/wiring-arduino-serial.svg)

**ใช้ทำอะไร**: มีอุปกรณ์อื่นอ่านค่ารถอยู่แล้ว (เช่น CAN logger, กล่อง ECU ที่ส่ง serial) แล้วอยากเอามาโชว์

### OBD BT — ต่อ OBD-II ผ่านบลูทูธ (รถยนต์)
ใช้ตัว **ELM327 Bluetooth Classic** (ตัวสีฟ้าที่ขายทั่วไป ชื่อ `OBDII`)
ขั้นตอนที่มันทำเอง: เปิดบลูทูธ → สแกนหา adapter (~10 วินาที) → จับคู่ (ลอง PIN 1234 / 0000 / 6789 / 1111 ให้เอง) → รีเซ็ต ELM → หาโปรโตคอลรถอัตโนมัติ → อ่านค่าวนไป
- **ก่อนต่อ ตัดมือถือออกจาก ELM327 ก่อน** (ปิดแอป OBD หรือปิดบลูทูธมือถือ) เพราะ ELM327 รับได้ทีละเครื่อง
- ชื่อไม่ต้องตรงเป๊ะ: เลือกเครื่องที่ชื่อมีคำว่า `OBD`, `ELM`, `V-LINK`, `VEEPEAK`, `KONNWEI`, `Vgate` … ให้อัตโนมัติ แล้วจำ MAC ไว้ บูตครั้งต่อไปต่อได้ทันทีไม่ต้องสแกน
- อ่าน: รอบ (PID 010C), ความเร็ว (010D), น้ำหล่อเย็น (0105), ไอดี (010F), แบตเตอรี่ (ATRV)
- อ่านรอบทุกๆ คำสั่งเว้นคำสั่ง เพื่อให้บาร์รอบลื่น (ได้ ~5–10 ครั้ง/วินาทีในรถ CAN ทั่วไป)
- PID ที่รถไม่รองรับจะข้ามเอง, หลุดการเชื่อมต่อจะต่อใหม่เอง
- ยังหาไม่เจอ: เปิด `pio device monitor` แล้วดูรายการเครื่องที่สแกนเจอ จากนั้นพิมพ์
  - `obd=AA:BB:CC:DD:EE:FF` เพื่อเลือก adapter เอง (กรณีชื่อแปลกๆ)
  - `obdpin=xxxx` เพื่อกำหนด PIN
  - `obd=scan` เพื่อลืม adapter ที่จำไว้แล้วสแกนใหม่

ข้อจำกัด: ตัว ELM327 แบบ **BLE อย่างเดียว** (เช่น Vgate iCar Pro BLE) ใช้ไม่ได้ ·
ระหว่างที่บลูทูธกำลังค้นหา ถ้าเปลี่ยนโหมด จะเปลี่ยนหลังการค้นหารอบนั้นจบ (สูงสุด ~10 วินาที)

### CUSTOM — เซ็นเซอร์ของคุณเอง (ง่ายที่สุดสำหรับค่าจริง)
แก้ไฟล์เดียว **`src/my_sensors.cpp`** โดยเอาโค้ดของคุณแทน 2 ฟังก์ชันในไฟล์ แฟลชใหม่ แล้วเลือก DATA SOURCE → CUSTOM
ตัวอย่างนี้ใช้ได้ครบ (แบต + รอบ ใช้ขาละ 1 เซ็นเซอร์):
```cpp
#include "gauge_input.h"

static PulseInput tach;                              // ประกาศครั้งเดียว ไว้นอกฟังก์ชัน

void mySensorsBegin() {
    analogSetPinAttenuation(35, ADC_11db);           // GPIO 35 วัดได้เต็มช่วง 0..3.1 V
    tach.begin(22, 60.0f / 2);                       // GPIO 22, 2 พัลส์ต่อรอบ (รถ 4 สูบ)
}

void mySensorsRead(GaugeInput &in) {
    in.voltage = readDividerVolts(35, 47000, 10000); // แบตผ่าน divider 47k/10k เข้า GPIO 35
    in.rpm     = tach.value();                       // สัญญาณรอบผ่าน opto เข้า GPIO 22
    // เซ็นเซอร์อนาล็อกตัวที่สองต้องใช้ขาของตัวเอง เช่น NTC ที่ GPIO 27
    // (ตั้ง EXT_SERIAL_RX_PIN -1 ใน config.h ก่อน):
    // in.coolant = readNtcCelsius(27, 2200, 2500, 3950);
}
```
- ใส่เฉพาะค่าที่มี ค่าที่ไม่ใส่จะแสดง `--`
- ฟังก์ชันช่วยใน `src/gauge_input.h`: `readDividerVolts` (วัดไฟ), `readNtcCelsius` (วัดอุณหภูมิ), `PulseInput` (นับพัลส์ → รอบ/ความเร็ว)
- ลองโดยไม่ต่อสาย: ตั้ง `EXAMPLE_FAKE_VALUES 1` ใน `my_sensors.cpp`
- มีค่ามาจากที่อื่นในโค้ด (เช่น callback ของ CAN) เรียก `gauge::set(CH_RPM, ค่า)` ได้จากทุก task (thread-safe)
- ขาว่างบน CYD: **GPIO 35** (ช่อง P3, อนาล็อก/อินพุตอย่างเดียว), **GPIO 22** (ช่อง CN1). GPIO 27 ใช้ได้ด้วยถ้าตั้ง `EXT_SERIAL_RX_PIN -1` (ปิดช่องรับ serial)

> ⚠️ ไฟในรถ 12–14 V และมีสัญญาณรบกวนแรง **ห้ามต่อเข้าขา ESP32 ตรงๆ** (รับได้สูงสุด 3.3 V)
> ใช้ตัวต้านทานแบ่งแรงดันสำหรับแรงดันไฟ และ opto-coupler (เช่น PC817) สำหรับสัญญาณรอบ

## 4. ใช้กับมอเตอร์ไซค์ (เช่น Honda Wave) ได้ไหม?

**สั้นๆ: จอใช้ได้ แต่โหมด OBD BT ใช้กับ Wave ไม่ได้ — ต้องใช้โหมด CUSTOM (ต่อเซ็นเซอร์เอง)**

| วิธี | Wave 110i / 125i (หัวฉีด PGM-FI) | Wave คาร์บู |
|---|---|---|
| OBD BT (ELM327) | ❌ ไม่ได้ — ขั้ว DLC 4 พินของ Honda ใช้โปรโตคอล K-Line เฉพาะของ Honda ไม่ใช่ OBD-II มาตรฐานของรถยนต์ | ❌ ไม่มี ECU |
| CUSTOM + ต่อสายเอง | ✅ ได้ | ✅ ได้ |
| Honda K-Line (อ่านจาก ECU ตรง) | 🔶 ทำได้ในทางเทคนิค แต่ยังไม่ได้ทำ (ต้องมีวงจร K-Line และรถจริงไว้ทดสอบ) | — |

### แนวทางต่อ Wave ด้วยโหมด CUSTOM

วงจรอ่านรอบและวัดแรงดันดูได้จาก[แผนภาพการต่อสาย](#แผนภาพการต่อสาย) ด้านบน
| ค่า | ต่อยังไง | ตั้งในโค้ด |
|---|---|---|
| **รอบเครื่อง** | สายสัญญาณขั้วลบคอยล์จุดระเบิด หรือสายปิคอัพ → **ผ่าน opto-coupler** → GPIO 22 | `tach.begin(22, 60.0f / N)` โดย N = พัลส์ต่อรอบ มอเตอร์ไซค์สูบเดียวส่วนใหญ่จุดระเบิด **1 ครั้งต่อรอบ** → `60.0f` (ตรวจโดยดูรอบเดินเบา Wave ≈ 1,400 rpm) |
| **ความเร็ว** | เซ็นเซอร์ความเร็ว (รุ่นที่มีเรือนไมล์ดิจิทัล) หรือติดแม่เหล็ก + Hall sensor ที่ล้อ → GPIO 27 (ต้องตั้ง `EXT_SERIAL_RX_PIN -1` ก่อน) | `PulseInput` scale = `3.6 × เส้นรอบวงล้อ(ม.) / พัลส์ต่อรอบล้อ` |
| **แรงดันแบต** | +12V → R 47k → GPIO 35 → R 10k → GND | `readDividerVolts(35, 47000, 10000)` |
| **อุณหภูมิเครื่อง** | Wave ระบายความร้อนด้วยอากาศ ไม่มีน้ำหล่อเย็น — ใช้เซ็นเซอร์ NTC วัดอุณหภูมิน้ำมันเครื่อง | ส่งค่าเข้า `in.coolant` แล้วเปลี่ยนป้ายเป็น `OIL TEMP` |

### ตั้งค่า `src/config.h` สำหรับมอเตอร์ไซค์
```cpp
#define RPM_MAX        10000     // เต็มสเกลบาร์ (Wave ประมาณ 9,000–10,000)
#define RPM_SHIFT       8000     // หรือปรับจากหน้าตั้งค่า
#define RPM_IDLE        1400
#define GEAR_COUNT         0     // ปิดการประมาณเกียร์ (หรือใส่อัตราทดของรถจริง)
#define PANEL1_LABEL  "OIL TEMP"
```

## 7. แก้ปัญหา

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| สีเพี้ยน/กลับสี | แฟลชอีก env (`esp32dev` ↔ `cyd-noinvert`) |
| OBD ค้างที่ `NO ADAPTER` | ELM327 ไม่ได้เสียบหรือไม่มีไฟ · มือถือยังต่อ ELM327 ค้างอยู่ (ปิดแอป/บลูทูธมือถือ) · เป็นรุ่น BLE อย่างเดียว · ดูรายการสแกนใน serial แล้วพิมพ์ `obd=<MAC>` |
| OBD ค้างที่ `NO ECU` | ยังไม่บิดกุญแจ ON / สตาร์ทเครื่อง |
| CUSTOM ขึ้น `NO INPUT` | ยังไม่ได้ใส่ค่าอะไรใน `mySensorsRead()` |
| SERIAL ขึ้น `WAIT DATA` | ยังไม่มีข้อมูลส่งเข้ามา (ต้องลงท้ายบรรทัดด้วย `\n`) |
| แตะไม่ตรง | ทัชเป็นแบบ resistive กดให้แน่นๆ ครั้งเดียว |

## ทำไมจอลื่น (เทคนิคการวาด)

- **ไม่ได้ใช้ LVGL** วาดเองด้วย C++ ลง buffer ใน RAM แล้วให้ TFT_eSPI ส่งขึ้นจอ (`pushImage`) ทีเดียว จอจึงไม่กระพริบ
- แบ่งจอเป็นช่อง (สถานะ, บาร์รอบ, ตัวเลขรอบ, ความเร็ว, กล่องขวา) **วาดใหม่เฉพาะช่องที่ค่าเปลี่ยน**
- ในช่องเดียวกันยัง**ส่งเฉพาะส่วนที่ขยับ**: บาร์รอบส่งแค่ช่วงระหว่างปลายแถบเก่ากับใหม่, ตัวเลขรอบ/ความเร็วส่งแค่หลักที่เปลี่ยน
  (ภาพที่ได้ตรงกับการวาดใหม่ทั้งจอทุกพิกเซล มีเทสตรวจทุกเฟรม)
- ค่าบนจอ**ค่อยๆ ไหล**เข้าหาค่าใหม่ (smoothing ตามเวลาจริง) จึงลื่นแม้ข้อมูลจริงมาแค่ 5–25 ครั้งต่อวินาที
- งานอ่านข้อมูลอยู่ core 0 งานวาดจออยู่ core 1 บลูทูธที่ค้างนานไม่ทำให้จอกระตุก
- SPI วิ่งที่ 80 MHz (ค่าเดิม 65 MHz จริงๆ วิ่งแค่ 40 MHz เพราะ ESP32 แบ่งความถี่ 80 MHz ได้แค่เป็นจำนวนเต็ม)
- วัดบนบอร์ดจริงด้วยคำสั่ง `bench`: **7.9 ms ต่อเฟรม (ทำได้ถึง 126 fps)** จากเดิม 23.6 ms (42 fps) ใช้งานจริงตั้งเพดานไว้ 60 fps (`UI_FPS`)
  ถ้าบอร์ดตัวอื่นเห็นจุดเพี้ยนหรือเส้นขีด ให้ลด `SPI_FREQUENCY` ใน `platformio.ini` กลับเป็น 40000000

## 8. โครงสร้างโปรเจค

```
src/
  main.cpp            ลูปหลัก, task ข้อมูล (core 0), ทัช, LED, เสียง, หน้าตั้งค่า
  config.h            ← ค่าที่ปรับบ่อย
  my_sensors.cpp      ← โค้ดเซ็นเซอร์ของคุณ (โหมด CUSTOM)
  gauge_input.h       ฟังก์ชันช่วยอ่านเซ็นเซอร์
  settings.h          ค่าตั้งค่าที่บันทึกลง NVS
  data/               แหล่งข้อมูล: sim, serial, obd, custom + bus กลาง
  ui/                 วาดหน้าจอ, หน้าตั้งค่า, ธีม, ฟอนต์
  assets/bg_*.h       พื้นหลัง 3 ธีม (อยู่ใน flash)
tools/
  host_preview/run.sh ดูหน้าจอบน Mac โดยไม่ต้องมีบอร์ด → PNG/GIF
  gen_bg.py           แปลง PNG → พื้นหลัง (มี --vivid เพิ่มความสดของเส้นสี)
  gen_font.py, make_fonts.sh, gen_slots.py, serial_feed.py
```

### ทดสอบ
```bash
~/.platformio/penv/bin/pio test -e native     # เทส 23 ชุดบน Mac: parser, model, การวาดจอ, หน้าตั้งค่า, ตัวจำลอง, ภาพธีม
```
ทุกครั้งที่ push, GitHub Actions จะรันเทสและ build เฟิร์มแวร์ทั้ง 2 แบบให้อัตโนมัติ

### ไฟล์ดีไซน์
- `tools/art/bg_*.png`: ภาพพื้นหลังต้นฉบับ 3 ธีม (ใช้กับ `gen_bg.py` เพื่อสร้าง `src/assets/bg_*.h` ใหม่)

### เพิ่มธีมใหม่
1. ทำภาพพื้นหลัง 320×240 (ตำแหน่งกรอบเหมือนเดิม)
2. `python3 tools/gen_bg.py ภาพ.png bg_ชื่อ src/assets/bg_ชื่อ.h`
3. เพิ่ม 1 แถวใน `src/ui/theme.cpp` และเพิ่มค่าใน enum `src/ui/theme.h`
